# humanoid_arm

Two 7-DoF arms with grippers on a common base: 16 actuators, driven by teleoperation or by joint position
targets through the bridge.

How to operate it — front ends, first enable, gravity feed-forward, calibration — is in
[`docs/arm_guide.md`](../docs/arm_guide.md). This page holds what is specific to this robot.

## Quick start

```bash
# simulation
python tools/fake_bridge.py --config humanoid_arm/humanoid_arm.yaml --grav-scale 1.0      # terminal 1
python tools/arm_web_jog.py --config humanoid_arm/humanoid_arm.yaml --gripper             # terminal 2 -> http://127.0.0.1:8780

# robot
python bridge.py --config humanoid_arm/humanoid_arm.yaml                                  # on the robot computer
python tools/arm_web_jog.py --config humanoid_arm/humanoid_arm.yaml --gripper --safety safe --bridge-host <robot-ip>
```

## Files

| File | Use |
|---|---|
| `humanoid_arm.yaml` | Configuration: joint table, motor parameters, gains, poses, gravity feed-forward, bridge port (9879) |
| `urdf/humanoid_arm.urdf` | URDF |
| `mjcf/humanoid_arm.xml` | MuJoCo model as exported from CAD |
| `mjcf/humanoid_arm_scene.xml` | Working scene used by the tools; generated by `tools/build_arm_model.py` — do not edit by hand |
| `meshes/` | STL meshes, simplified for display and collision. Mass, centre of mass and inertia come from the URDF / MJCF, not from the meshes |

## Joints

The model uses leg-style joint names. Read them as follows; prefix `l_` for the left arm, `r_` for the right.

| # | Joint | Function | Range (rad) | Left id (CAN1) | Right id (CAN2) | Motor |
|---|---|---|---|---|---|---|
| 1 | `hip_pitch_joint` | Shoulder pitch | ±1.309 | 1 | 9 | RS06 |
| 2 | `hip_roll_joint` | Shoulder roll | left −1.222 … 0.349, right −0.349 … 1.222 | 2 | 10 | RS06 |
| 3 | `hip_yaw_joint` | Upper-arm yaw | ±1.047 | 3 | 11 | RS00 |
| 4 | `knee_joint` | Elbow | −1.920 … 0 | 4 | 12 | RS06 |
| 5 | `link4_joint` | Wrist | ±1.571 | 5 | 13 | RS02 |
| 6 | `link5_joint` | Wrist | ±1.571 | 6 | 14 | RS00 |
| 7 | `link6_joint` | Wrist | ±2.094 | 7 | 15 | RS00 |
| 8 | `gripper_joint` | Gripper: 0 = fully open, 1.955 = closed; each finger travels 43 mm | 0 … 1.955 | 8 | 16 | RS05 |

Each arm has its own CAN bus on the MC02 board: left arm on CAN1 (`mc02:0`), right arm on CAN2 (`mc02:1`).

Motor peak / rated torque: RS06 36 / 11 N·m, RS02 17 / 6 N·m, RS00 14 / 5 N·m, RS05 (gripper) 5.5 / 1.6 N·m.

## Poses

- **Zero pose (`home_pose`)**: both arms hanging straight down, grippers pointing down, fingers fully open.
  This is the pose used for calibration, and the pose in which the arm needs no torque.
- **Ready pose (`ready_pose`)**: elbows bent, hands in front of the body. Shoulder and elbow gravity torque
  stay below the motors' rated torque here, so the arm can stay in this pose.

## Gravity and heat

The arms are heavy for their actuators. With an arm stretched out horizontally the shoulder has to supply
most of the motor's peak torque — far above its rated continuous torque. Hold stretched-out poses only
briefly, and rest in the ready or home pose. The shoulder and elbow motors are the ones that heat up.

Because of this, teleoperation requires the gravity feed-forward: `gravity_ff.scale` in the config is 0.45,
measured on the robot (the model's link masses are higher than the real ones, so a scale of 1.0 makes the
arms rise by themselves). Verify it on your unit as described in the arm guide, step 3.

## Front ends available

Web sliders, keyboard, mouse drag, lead by hand (the other arm mirrors the one you move), VR controllers and
camera (both experimental). See [`docs/arm_guide.md`](../docs/arm_guide.md), section 2.
